# CLAUDE.md

Technical guide for agents working on this repository. Public file: no personal data, local paths or account links.

## Project
Cross-platform SFTP/FTP client built on the FileZilla 3.71.1 engine, with a GitHub tab (like GitHub Desktop) and safe, version-aware server sync. Generic tool: nothing specific to any particular server.
- Product name: **Parom** (Russian for "ferry"; formerly the working name TOTzilla). It lives in ONE place: `productName` in `app/src-tauri/tauri.conf.json` (window title, installer, credential service, user agent). Never "-zilla" (FileZilla trademark). The GitHub App slug `totzilla-sync` still carries the working name (renamed on GitHub separately; `APP_INSTALL_URL` follows it).
- Rename compatibility: on first start the old data folders (`org.totzilla.app`) are copied to the new identifier and saved passwords to the new credential service (`src-tauri/src/migrate.rs`); the old marker `/.totzilla` and `.totzilla-ignore` are still read (the marker is replaced by `/.parom` on the next write).
- License: GPLv3 or later. fzssh is AGPLv3, so distributed binaries follow AGPLv3 terms. Keep upstream copyright headers, mark modified files, keep NOTICE up to date.
- Remove FileZilla branding, client identification strings and update-check URLs; updates come from GitHub Releases.

## Working rules
- Builds run only in GitHub Actions (windows-latest + MSYS2 UCRT64). No local C++ toolchain is assumed. Use `gh` to trigger runs and read failed logs.
- Work on branches. Commit messages: one English line, imperative, <= 72 chars, optional prefix (docs, feat, fix, ci, build), "Fixes #N" when closing issues.
- Do not claim something works until CI or a test proves it.
- Code, comments, commits and docs in English.
- Cross-platform code only (no Windows-only APIs). Linux: experimental, CI-built. macOS: later.

## Backend: FileZilla engine
- `src/engine`, `src/include` (~26k LOC, no wxWidgets) build into `libfzclient-private`; `src/commonui` into `libfzclient-commonui-private`.
- API: `CFileZillaEngine::Execute(command)` and `GetNextNotification()`. Commands: connect, list, transfer, del, removedir, mkdir, rename, chmod, raw. Protocols: FTP, SFTP (libfzssh-client >= 1.4, not PuTTY), HTTP, Storj.
- Dependencies: libfilezilla >= 0.57.0, fzssh >= 1.4.0, gnutls, nettle, gmp, argon2, sqlite3. On Windows CI they come from MSYS2 UCRT64 packages (`mingw-w64-ucrt-x86_64-libfilezilla`, `-fzssh`, ...).
- Configure: `--enable-gui=no --disable-locales --disable-shellext --disable-storj --disable-manualupdatecheck --disable-autoupdatecheck --with-pugixml=builtin`, then `make -C src`.
- The wx UI (`src/interface`, ~66k LOC) is not used; it is replaced entirely.

## Daemon: paromd
C++ process wrapping the engine. Owns the transfer queue (SQLite), sites, settings, sync/marker/backups. Talks JSON-RPC over stdio or a local pipe.

## UI: Tauri
- Tauri (WebView2 on Windows) + web UI. File lists are virtualized: 100k rows must scroll smoothly.
- GitHub features live in the app layer: OAuth device-flow sign-in (prefer a GitHub App with fine-grained permissions: contents read, issues read/write, pull requests read), token in the OS credential store, REST for issues/PRs, libgit2 (git2-rs) for local git.

### Themes

- Light: bg #fff, panel #fafafa, line #e2e2e2, text #111, muted #666.

### i18n
- JSON files in `locales/`; `en.json` is the source of truth; missing keys fall back to English.
- ICU MessageFormat with plural rules (Russian needs one/few/many/other).
- The app can download community translations from GitHub (public, no login).
- Russian (`locales/ru.json`, formal "вы", full one/few/many/other plurals) ships with the app; `lib/i18n.test.ts` checks plurals and that it covers every English key. The language preference defaults to "system" (the system language when a translation exists, else English; `resolveLocale`).

## Sync marker
One small file on the server, `/.parom` (~300 bytes; `/.totzilla` from before the rename is still read). Fields: format version, repo, last deployed commit SHA, tree fingerprint (hash over managed files: path+size+hash), who (GitHub login or machine), when (UTC), lock `{by, since, ttl}` or none.
- History is NOT stored on the server. Per-user history, backups and logs live locally in the app data dir (`{history,backups,logs}`).
- On connect, read the marker:
  - same SHA: up to date;
  - server SHA is an ancestor of local HEAD: normal update, no prompt;
  - unknown/different SHA (someone else synced) or fingerprint mismatch (manual edits; diff against the git tree at that SHA shows which files): "Versions differ" dialog with Cancel / Show differences / Sync anyway, and "Back up the server first" checked by default.
- First connect to a server: ask once to create the marker (Not now / Never for this server / Create), remembered per server ("Ask again" in Preferences). If declined, compare repo files with server files by size+hash (slower, no author info).
- Lock: write lock with a nonce, re-read after a short delay, abort on mismatch. SFTP has no atomic compare-and-swap, so a small race remains (document it in the UI/docs). Upload to a temp name, then rename.
- Managed paths: `.parom-ignore` in the repo (gitignore syntax; `.totzilla-ignore` still read); `!pattern` means never upload or overwrite (e.g. `!data/**`).
- Sync steps (progress dialog): check marker, back up, upload N files, update marker, optionally close the linked issue with a comment, optionally run a post-sync command (e.g. restart).

## Roadmap
- M0a: engine library builds on Windows CI. M0b: console spike (SFTP connect, list, upload) built in CI.
- M1: paromd (then totzillad) JSON-RPC + Tauri shell + Files tab.
- M2 (done): Site Manager (sites in the daemon store, passwords in the OS credential store), Preferences (live where the feature exists), themes, i18n loader, context menus (edit, download, rename, delete, new folder), edit-in-place with upload on save, remembered host keys and certificates (`trust.json`), "apply to all" for file exists.
- Still open from M2: persistent transfer queue in the daemon (SQLite) and simultaneous transfers; message log panel.
- M3 (done): marker on the server, server state and hand-edit detection, lock, backups (folder configurable) with restore, deploys the committed version (git export), history, Preferences: Marker and history. Not done on purpose: deleting files removed from the repo on the server; the post-sync command runs on this computer (SFTP cannot run commands).
- Drag and drop: rows between the local and server panes (mouse events, `lib/panedrag.svelte.ts`; the webview's HTML drag and drop is taken by Tauri's file drop), and files or folders from the system file manager onto the server pane (upload). Out of the window (to Explorer and other apps) through tauri-plugin-drag (`lib/dragout.ts`): local files and folders directly; server files are downloaded to a temp folder when the drag starts (files only, up to 200 MB).
- M4 extras (done): selection count and size in each pane header; message log panel (status bar → Log); automatic reconnect (3 tries, Preferences → Timeouts); images in issues open in an in-app viewer; new issues from the app (title, Markdown with GitHub preview, labels).
- Server load: FTP listings cost a command and a data connection each and hosts rate-limit bursts. Sync lists each folder once per operation (cache), spaces listings out, skips MKD for known folders, and does not re-walk the server after a sync. Keep it that way. A sync does not walk the whole server for hand edits: it checks the files it overwrites (their folders are listed for the backup anyway); the full walk is "Scan for edits" in the sync bar, or on every check if Preferences ask for it. Only the first sync (marker without a commit) compares every file.
- M3: marker + sync + backups + dialogs.
- M4: GitHub tab. Sign-in: GitHub App device flow (client ID in `src-tauri/src/github.rs`; user tokens do not expire) or a fine-grained personal access token; the token stays in Rust (credential store), the UI calls REST by path. Changes (commit ticked files), History (badges from the marker), fetch / fast-forward pull / push over HTTPS (git2 `https`), Issues and Pull requests (comment, close, reopen, merge, check runs), Backups per site, and after a sync the issues the deployed commits fix are commented on and closed. Issue, pull request and comment bodies: GitHub-rendered Markdown (`body_html`) passed through the app's own allowlist (`lib/markdown.ts`); links open in the browser. Not yet: branch switching, reviews.
- Design stage, done so far: custom title bar (`decorations: false`; drag region, menus File / Edit / View / Server / Help in `MenuBar.svelte`, shortcuts in `lib/commands.svelte.ts`, own window buttons, Help → About); bundled fonts (Inter, JetBrains Mono via @fontsource-variable, `--font-ui` / `--font-mono`); Lucide icons (@lucide/svelte) for file types (`FileIcon.svelte`) and the eye (Preferences open from File and the account menu). App icon: "_P" in thin white lines on true black (`src-tauri/icons/source.svg`; regenerate with `npx tauri icon src-tauri/icons/source.svg`, then delete the android/ and ios/ folders it adds); the title bar shows "_Parom". Live accent colour (Preferences → Interface; `data-accent` on the root sets `--accent`, selection marks, focus and primary buttons); motion tokens `--motion` / `--motion-fast` (none with reduced motion), dialogs and menus pop in, rows that appear or change flash; own drop-down (`Select.svelte`) instead of system selects; folder colour labels (right-click, kept in preferences on this computer); "?" on server folders not listed yet in the session, and listings of folders seen before show at once; avatars of authors and co-authors (trailers) in History. The GitHub tab and its pages stay mounted once opened (typed text survives tab switches; one comment draft per issue; the new-issue draft survives closing the dialog); columns there are resizable (`prefs.widths`); the repository is fetched quietly at start, on focus after 5 minutes and every 10 minutes; Markdown editor with a formatting bar (`MarkdownEditor.svelte`) for issues and comments. Svelte transitions use `lib/motion.ts` (`ms()` is 0 with reduced motion): Preferences and Site Manager pages slide in, the drag label cross-fades Copy/Move; "_" blinks while files move and the name waves on hover; a ferry sails in the footer corner of Preferences and Site Manager (`Ferry.svelte`). Hidden addresses are blurred (`.secret`) or replaced by a word (Preferences). Shift: Shift+Delete deletes without asking (local files still go to the Recycle Bin), Shift+right-click adds Copy as path / Show in Explorer / Copy as URL. Backups → "Back up now" (`sync.backupNow()`, reason "manual"). Clickable avatars (`Person.svelte`) open GitHub profiles; the account menu has Open profile, Preferences, Sign out. Synchronized browsing (View, Ctrl+Y, link button in the server pane; `lib/browsing.ts`): inside a site's local folder and server folder, opening a folder on one side opens the same relative folder on the other; when that folder is not there, the other side stays as it is (no error, no listing request for a folder missing from the list shown). Folders with the same name in both panes can be tinted grey (`lib/twins.svelte.ts`, Preferences → File lists; colour labels win); the first time such folders show up the app asks once (any answer, closing included, is final), with an option to turn on synchronized browsing. Preferences → File lists can show local paths with "/" (display and Copy as path only; the lists keep the system's form). The drag label shows "/name" from the server, the local separator from this computer. Issue lists and opened issues are cached for the session (`listCache`, `detailCache` in `lib/issues.svelte.ts`); unchanged entries keep their HTML so images are not fetched again. File menu: file operations on the pane used last (`lib/fileops.svelte.ts`; each pane registers), grey while nothing is selected. Several windows can run at once, each with its own connections: windows keep `instances/<pid>.json` fresh in the app data dir (`src-tauri/src/instances.rs`), and the Files tab warns once per connection when another window is on the same server (Preferences → File lists turns it off). Uncommitted changes: a short note in the sync bar (files in the tooltip) and a notification dot on the GitHub tab (`.blob`). Issue labels in their GitHub colours (`IssueLabel.svelte`: text mixed with the theme's strongest text, readable in both themes). Empty states (`EmptyState.svelte`) for empty folders, the server pane before connecting (first run: "Create a site" opens the Site Manager with a new site), Changes, Issues. Light theme text colours keep 4.5:1 on selected rows. The ferry (`Ferry.svelte`) carries a crate between two piers. Changes: right-click menu like GitHub Desktop (discard with confirmation: HEAD's version back, new files to the Recycle Bin, `gitrepo::discard`; ignore file or extension; copy paths; show in Explorer); the open repository's folder is watched (`src-tauri/src/watch.rs`, notify; event "repo-fs" at most every 300 ms, `.git` ignored except index and HEAD), so Changes follow the disk live; commits whose ticked files no longer differ from HEAD are refused. Windows 11 snap layouts: resting the mouse on the own maximize button sends Win+Z (`src-tauri/src/snap.rs`, the one Windows-only API, a no-op elsewhere; Preferences → Interface). Motion with character: the marker under the active tab or page crawls to the next one like a caterpillar (`lib/indicator.ts`, `use:indicator` on top tabs, GitHub sidebar, Preferences pages, Site Manager tabs); menus unroll from their button with items dropping in one after another (`.menu-unroll`); the Files and GitHub tabs slide in from their side. Issues and pull requests have a right-click menu (open, view on GitHub, copy link / number / title / "Fixes #N", close or reopen). Synchronized browsing is remembered (`prefs.syncBrowse`). Discord Rich Presence (optional, off by default, Preferences → Interface): `src-tauri/src/discord.rs` speaks Discord's local IPC itself (pipe `discord-ipc-N` on Windows, socket on Linux/macOS; no network, no extra crate) and keeps to the rate limit (newest activity, at most every 4 s); `lib/discord.svelte.ts` decides what is shown: what the app is doing and since when, never server addresses or site names, the repository name only on request and only for public GitHub repositories. Discord application ID in `discord.rs` (public). Spacing follows the boards: Preferences 880 x 600 (220 px nav, 20 x 28 page), Site Manager 900 x 600 (250 px tree), GitHub columns 360 / 420 / 400 by default, detail panes 18 x 22.

A tag `vX.Y.Z` builds, publishes a GitHub release (pre-release below 1.0 or with a suffix) with `docs/releases/X.Y.Z.md` as notes, and rewrites `latest.json` in the fixed release `updater` (the update feed; GitHub's latest-release link skips pre-releases). NSIS installer per user (no administrator rights), not code-signed (README explains SmartScreen). Linux AppImage comes after 0.9.0 (needs the engine, fzssh and paromd built on Linux).
