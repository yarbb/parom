**New**
- **History menu like GitHub Desktop**: right-click a commit to amend it, reset to it, check it out, move it up or down, revert it, create a branch or a tag from it, cherry-pick it onto another branch, or copy its SHA or tag. Anything that rewrites commits works only on commits not pushed yet; items that do not apply are grey. Commits show their tags and an ↑ until they are pushed.
- **A site's folder can be a folder inside its repository** (for example `serverFiles/`): sync, the server comparison and synchronized browsing use that folder, the GitHub tab the whole repository. The Site Manager says which repository it belongs to.
- **Parom notices when a site's files move inside the repository**: Changes offers to update the site, and if the move is already committed the sync bar says so and waits until the site follows, so a sync never uploads the new folder next to the real files. A site whose folder is gone offers *Find the folder…*.
- **One error window for all errors**: click any red error line (GitHub tab, sync bar, connect bar, file lists, server replies in the status bar) for the whole text with Copy; long errors open it by themselves, and *N errors* in the status bar lists the recent ones.
- **Automatic updates, if you want them**: Preferences → Updates → *Install updates automatically* (off by default). A new version downloads in the background and installs when you close Parom (not during transfers, a sync or open conflicts); the next start shows what is new.

**Fixed**
- **Huge Changes lists no longer freeze the window**: after moving folders with tens of thousands of files, Changes draws only the rows in view, and moved files show as one *renamed* row instead of a deleted and a new one.
- The yellow dot on *Update to …* in the status bar sits inside the button instead of being cut off.

**Also new since 0.9.4** (from 0.9.5)
- No more freeze at start when a mapped network drive is slow to answer.
- The update window shows the notes formatted instead of raw Markdown.
